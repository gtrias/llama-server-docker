# Qwen3.6 MTP 1.8x Speedup Upgrade Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Update the local llama-server MTP setup to match the new Unsloth/llama.cpp Qwen3.6 MTP recipe announced on r/unsloth (1.8x faster, up from 1.4x).

**Architecture:**
The MTP speculative-decoding path lives in three files: `entrypoint.sh` (passes `--spec-*` flags to `llama-server`), `docker-compose.mtp.yml` (sets the env vars), and `Dockerfile.mtp` (builds a llama.cpp that includes the MTP support and the new `--spec-draft-p-min` flag). We rebuild the image against the current llama.cpp `master`, rename the spec type, bump n-max, and add the new p-min flag — all controlled by env so we can revert by toggling values.

**Tech Stack:** bash, Docker, llama.cpp (master + PR #22673), NVIDIA CUDA 12.8.

**Reference:** [r/unsloth post](https://www.reddit.com/r/unsloth/comments/1tdw5jq/qwen36_mtp_unsloth_ggufs_now_18x_faster/) by `u/danielhanchen`. Key changes:
- `--spec-type mtp` → `--spec-type draft-mtp`
- `--spec-draft-n-max` 2 → 6
- New flag: `--spec-draft-p-min 0.75` (use `0.0` to restore previous behavior)

## Task 1: Add `SPEC_DRAFT_P_MIN` support to `entrypoint.sh`

**Files:**
- Modify: `entrypoint.sh:107-113`

**Step 1: Edit entrypoint.sh to read and pass the new flag**

Replace the MTP block (lines 107–113) with:

```bash
# MTP speculative decoding (requires PR #22673 build)
SPEC_TYPE=${LLAMA_ARG_SPEC_TYPE:-""}
SPEC_DRAFT_N_MAX=${LLAMA_ARG_SPEC_DRAFT_N_MAX:-"6"}
SPEC_DRAFT_P_MIN=${LLAMA_ARG_SPEC_DRAFT_P_MIN:-""}
if [ -n "$SPEC_TYPE" ]; then
    CMD_ARGS+=("--spec-type" "$SPEC_TYPE" "--spec-draft-n-max" "$SPEC_DRAFT_N_MAX")
    if [ -n "$SPEC_DRAFT_P_MIN" ]; then
        CMD_ARGS+=("--spec-draft-p-min" "$SPEC_DRAFT_P_MIN")
    fi
    log_config "  Speculative decoding: $SPEC_TYPE (draft-n-max=$SPEC_DRAFT_N_MAX, draft-p-min=${SPEC_DRAFT_P_MIN:-default})"
fi
```

Notes:
- Default for `SPEC_DRAFT_N_MAX` bumped 3 → 6 (per post).
- `SPEC_DRAFT_P_MIN` defaults to empty (so old llama.cpp builds that don't know the flag still work). The compose file will set it explicitly.

**Step 2: Lint check**

Run: `bash -n entrypoint.sh`
Expected: exits 0, no output.

**Step 3: Commit**

```bash
git add entrypoint.sh
git commit -m "feat(mtp): add SPEC_DRAFT_P_MIN env, bump SPEC_DRAFT_N_MAX default to 6"
```

The `--spec-draft-p-min` flag and the `draft-mtp` rename landed in llama.cpp *after* PR #22673 was opened. The `Dockerfile.mtp` already clones `master` then merges PR #22673, so a fresh build should pick everything up.

**Files:**

**Step 1: Rebuild without cache**

Run from repo root:

```bash

```

Expected: build finishes successfully, ends with `Successfully tagged llama-server:mtp` (or compose's equivalent). Watch for `cmake --build` errors — if the merge of PR #22673 fails because master already contains it, the Dockerfile's fallback `git checkout --theirs ...` will handle it.

**Step 2: Verify the built `llama-server` knows the new flag**

Run:

```bash
docker run --rm --entrypoint /app/llama-server llama-server:mtp --help 2>&1 | grep -E "spec-(type|draft-(n-max|p-min))"
```

Expected output includes lines for all three:
- `--spec-type ...`
- `--spec-draft-n-max ...`
- `--spec-draft-p-min ...`

If `--spec-draft-p-min` is missing → llama.cpp master doesn't yet contain the feature in your fetched commit. Stop here and report; options: (a) wait for upstream, (b) cherry-pick the relevant commit, (c) leave `LLAMA_ARG_SPEC_DRAFT_P_MIN` unset (the entrypoint guard skips the flag, so the image still runs on the old behavior).

**Step 3: Verify `draft-mtp` is the accepted spec-type name**

Run:


Expected: the help text mentions `draft-mtp` (or accepts it). If only `mtp` is listed, the rename hasn't landed yet — set `LLAMA_ARG_SPEC_TYPE=mtp` in compose as a temporary fallback and note it in the commit message.

## Task 4: Smoke-test the running stack

**Files:**

**Step 1: Start the stack**

```bash
docker compose -f docker-compose.yml -f docker-compose.mtp.yml up -d
```

**Step 2: Confirm flags reached the server**


Expected: `Speculative decoding: draft-mtp (draft-n-max=6, draft-p-min=0.75)`

**Step 3: Health probe**

Run: `curl -sf http://localhost:8080/health`
Expected: HTTP 200, JSON `{"status":"ok"}` (or equivalent — llama-server returns 200 when ready).

**Step 4: Generation probe with the MTP model**

Run:

```bash
curl -s http://localhost:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "qwen36-27b-mtp",
    "messages": [{"role":"user","content":"Say hello in five words."}],
    "max_tokens": 32
  }' | jq '.choices[0].message.content, .usage'
```

Expected: a short answer + a `usage` block with non-zero `completion_tokens`. The first request will load the model — give it up to ~60s. If the server returns an error about an unknown spec-type, go back to Task 3 Step 3.

**Step 5: Quick perf sanity check (optional but recommended)**

Compare tokens/sec against the pre-upgrade behavior. Run two passes — one with `LLAMA_ARG_SPEC_DRAFT_P_MIN=0.0` (old behavior) and one with `0.75`:

```bash

  -d '{"model":"qwen36-27b-mtp","messages":[{"role":"user","content":"Write a 200-word story about a llama."}],"max_tokens":300}' \
  | jq '.usage'

# Pass B — new behavior
docker compose -f docker-compose.yml -f docker-compose.mtp.yml up -d --force-recreate

time curl -s http://localhost:8080/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"model":"qwen36-27b-mtp","messages":[{"role":"user","content":"Write a 200-word story about a llama."}],"max_tokens":300}' \
  | jq '.usage'
```

Expected: Pass B is meaningfully faster (~1.3x is typical real-world; the post's 1.8x is best-case). If B is slower, MTP draft acceptance is poor for your prompts — revert by setting `LLAMA_ARG_SPEC_DRAFT_P_MIN=0.0`.

## Rollback

If anything regresses:

1. Set `LLAMA_ARG_SPEC_DRAFT_P_MIN=0.0` in `docker-compose.mtp.yml` — restores pre-upgrade speculative behavior with zero code changes.
2. If `draft-mtp` isn't recognized by the built llama-server, change `LLAMA_ARG_SPEC_TYPE` back to `mtp`.
3. Full revert: `git revert <commits from tasks 1–2>` and `docker compose build --no-cache`.
